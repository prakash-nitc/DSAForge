title: What interviewers actually notice
---

| Signal | Reads as |
| --- | --- |
| ArrayDeque instead of Stack | Knows the Java library, not just the syntax |
| Stating complexity unprompted | Thinks about cost by default |
| Naming variables meaningfully under time pressure | Has written real code |
| Volunteering edge cases before being asked | Tested code before |
| Saying 'this is O(n²), let me see what's wasteful' out loud | Optimises deliberately rather than by luck |
| Asking one sharp clarifying question, not five vague ones | Reads specifications carefully |
| Writing the brute force first and saying why | Won't freeze when the clever idea doesn't come |
| Using long for an accumulator without being told | Has been burned and learned |

> [!WARNING]
> **And the negatives**
>
> Silence while thinking. Coding before agreeing on the approach. Arguing with a hint. Not knowing the complexity of a structure you just used. Being unable to explain a line you wrote thirty seconds ago.
